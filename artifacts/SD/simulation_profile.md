# 시뮬레이션 동작 프로파일 P1

2026-11-06 사용자가 “이제 simulator까지 완성해줘”로 구현·시스템 테스트 진행을 지시하고, 미정 동작 질문에 **“기본값으로 진행”**이라고 답했다. 이 프로파일은 그 답변의 기본값을 실행 가능한 이산 모델로 상세화한다. 원본 예비 요구사항을 변경하지 않으며 실제 HW 사양을 의미하지 않는다.

| SA 미정 항목 | 실행 모델의 기준 |
|---|---|
| Q1 회피 시작 | 전방 감지 시 회피. 측면만 감지한 경우 직진 유지 |
| Q2 회전 | 비어 있는 좌측 우선, 좌측이 막히고 우측이 비면 우측. 모두 막혀 후진한 뒤 두 측면도 막혔으면 제자리 좌회전. 회전 90도/1틱이며 회전 후 다음 틱에 전방을 재검사 |
| Q3 후진 | 1칸/1틱 후 회전. 후방 센서는 추가하지 않음. 모델은 벽·장애물 관통을 막고 이동 차단을 기록 |
| Q4 강화 | 통상 출력 1, 강화 출력 2라는 논리 수준. 먼지 감지 틱을 포함한 청소 가능 3틱 동안 강화. 재감지는 3틱으로 갱신 |
| Q5 충돌 정책 | 회피 우선, 청소·물걸레 중지, 강화 타이머 일시정지. 회피 중 감지한 먼지는 pending으로 보존하여 청소 재개 시 3틱 강화 |
| Q6 물걸레 | 청소 수행 시 함께 수행, 회피 시 함께 중지. 강화는 흡입 출력 수준만 변경 |
| Q7 실행 | 한 틱은 관측→C 제어→환경 적용 1회. 자동 청소 실행 범위의 초기 상태는 Forward/통상 출력. UI 시작·일시정지는 실행 환경의 제어이며 RVC 외부 입력에 추가되지 않음 |

지도는 10×10, 좌상단 (0,0), 초기 위치 (4,4), 초기 방향 북쪽이다. 방향은 북·동·남·서이며 그리드 밖은 장애물로 감지한다. 먼지 센서는 현재 칸을 감지한다. 청소·물걸레 효과는 이동 전 현재 칸에 적용한다. 새 칸은 다음 틱에 청소한다. 지도 효과와 위치는 Python 환경 모델이 담당하며 동작 결정은 C만 수행한다.

## 설계의 구체화

[Structure Chart](structure_chart.md)의 13개 모듈과 12개 호출 관계를 유지한다. 모듈의 C 자료형과 다음 관리 인터페이스는 논리 인터페이스를 구현하는 세부 사항이다.

- stdin의 센서 네 값 한 줄이 기존 외부 센서 입력 네 개를 운반한다. stdout JSON 한 줄이 명령 및 관찰 전용 진단값을 운반한다.
- FILE 포인터는 포트 접근을 위한 주입 인자이다. 새 RVC 기능 입력이 아니다.
- 센서 획득의 반환 상태는 VALID/EOF/INVALID로 구분한다. 이는 전송 종료·오류 처리용이며 정상 센서 4개의 의미나 FSM 입력을 변경하지 않는다.
- FSM 상태는 `fsm.c`의 불투명 컨텍스트에만 저장한다. `fsm_create`/`fsm_destroy`는 생명주기 보조 함수이며 기존 기능을 우회하지 않는다. 상위 모듈에는 불투명 포인터만 전달한다.
- FSM은 읽기 전용 상태 복사본을 반환한다. 타이머·플래그·이전/현재 상태를 시뮬레이터가 표시하기 위한 관측이며 새 동작 정책이 아니다.
- 리셋은 새 C 실행 컨텍스트로 복원한다. 로컬 백엔드는 누적 센서 입력을 최대 100줄까지 C에 재생하여 마지막 출력을 사용한다. 이 방식은 세션 간 상태 공유를 방지하고 같은 입력의 결정성을 보장한다.
- 입력·출력 모듈의 포트 읽기/쓰기 이외에 JS나 Python에서 회전·강화 판단을 재구현하지 않는다.

이 프로파일의 상세 기준은 UI와 문서에 공개한다. 실제 하드웨어의 완료 신호, 속도, 안전 제어, 전체 면적 커버리지는 범위 밖이다.
